# Cassette

A simple, offline, ad-free music player for Android, built with Flutter. Cassette scans your phone's local audio files, lets you build playlists and favorites, and plays in the background with full lock-screen and notification controls.

## Features

- Auto-scans your device's music library on first launch
- Local playback only — no ads, no accounts, no streaming
- Background playback with media notification (play/pause/skip from the lock screen)
- Playlists, favorites, queue panel, shuffle, repeat-one
- Spinning vinyl disc UI with album label
- Light and dark themes (defaults to dark)
- Persistent state via `SharedPreferences` — your library and playlists survive restarts

## Running the app from VS Code

### One-time setup

1. Install the **Flutter SDK** (3.12 or newer): https://docs.flutter.dev/get-started/install/windows
2. Install **Android Studio** (just to get the Android SDK + platform-tools). After install, open it once and let it download the SDK.
3. In VS Code, install the **Flutter** extension (publisher: Dart Code). It pulls in the Dart extension automatically.
4. Confirm everything is wired up:
   ```powershell
   flutter doctor
   ```
   Resolve anything marked with an `X`. The Android toolchain section is the one that matters here.

### Running on your phone (USB)

1. On your phone, enable **Developer options** → **USB debugging** (Settings → About phone → tap Build number 7 times, then Settings → System → Developer options).
2. Plug the phone in via USB and tap **Allow USB debugging** when the prompt appears.
3. Clone the repo and open the project folder in VS Code (`File → Open Folder...`).
4. Bottom-right of VS Code, click the device selector and pick your phone.
5. Hit **F5** (or Run → Start Debugging). VS Code builds, installs, and launches the app with hot-reload attached.
6. While running:
   - Save a `.dart` file → hot reload (instant, keeps state)
   - `Ctrl+F5` → hot restart (full app restart, clears state)
   - `Shift+F5` → stop

### Running from the terminal

If you'd rather skip VS Code's debugger:

```powershell
flutter pub get          # install dependencies (only needed once or after pubspec changes)
flutter devices          # confirm your phone is listed
flutter run              # builds, installs, and runs on the first available device
```

To target a specific device: `flutter run -d <deviceId>` (the ID comes from `flutter devices`).

### Building a release APK

```powershell
flutter build apk --release
```

Output lands at `build\app\outputs\flutter-apk\app-release.apk`. Copy it to your phone and install (you'll need to allow installation from unknown sources).

## Project layout

A Flutter project is split between Dart code (cross-platform UI and logic) and platform-specific folders that host the Android/iOS shells. Here's what each top-level folder does.

### Top-level folders

| Folder | What it does |
|---|---|
| `lib/` | All Dart source code. This is where the app is actually built — UI screens, services, models, theme. **You'll spend ~95% of your time here.** |
| `android/` | Android-specific project (Gradle, Kotlin, manifest, app icons). Auto-generated by Flutter, but we edit `AndroidManifest.xml` for permissions and add Kotlin code under `app/src/main/kotlin/` for the native MediaStore query. |
| `ios/` | iOS shell (we don't ship iOS, but Flutter generates it anyway). Safe to ignore. |
| `assets/` | Bundled resources. `assets/fonts/` holds the two custom fonts; `assets/branding/` holds the logo used to generate the launcher icon. Anything here must be declared in `pubspec.yaml` to be loaded at runtime. |
| `test/` | Unit and widget tests. Runs via `flutter test`. |
| `build/` | Generated build output (APKs, intermediate compile artifacts). Gitignored — never commit. |
| `.dart_tool/` | Dart's package and codegen cache. Gitignored. |
| `pubspec.yaml` | Project manifest: dependencies, asset declarations, font registrations, app version, launcher icon config. The Dart equivalent of `package.json`. |
| `pubspec.lock` | Exact versions of every resolved dependency. Commit this so the whole team builds against the same versions. |
| `analysis_options.yaml` | Linter rules (uses `flutter_lints`). |

### Inside `lib/`

```
lib/
  main.dart                  app entry point — initializes background audio, sets up the theme, mounts HomeScreen
  models/                    plain data classes (no Flutter dependencies)
    song.dart                  Song + JSON serialization
    playlist.dart              Playlist + copyWith
  services/                  app logic, no UI — call these from screens
    music_service.dart         playback engine, queue management, library scanning, favorites/playlists state
    storage_service.dart       persistence layer — wraps SharedPreferences
  screens/                   full-page UIs reachable from navigation
    home_screen.dart           Songs list, top-bar scan/pick actions, bottom nav, mini-player
    player_screen.dart         full-screen player with vinyl disc, progress bar, queue panel
    playlists_screen.dart      Liked Songs + user-created playlists
    settings_screen.dart       dark-mode toggle and About blurb
  widgets/                   reusable UI pieces composed inside screens
    song_tile.dart             a single song row (used in lists)
    mini_player.dart           the persistent bottom bar showing the current song
  theme/
    app_theme.dart             Material 3 light/dark themes + brand-font helper
```

The split between `services/` and `screens/` is intentional: services hold state and logic, screens just render that state and forward user actions. This keeps screens dumb and easy to change without touching playback behavior.

## Advanced concepts used in this app

These are the parts of the codebase that go beyond a beginner Flutter tutorial. Each one is annotated with where to find it.

### 1. State management with `ChangeNotifier`

`MusicService extends ChangeNotifier` (`lib/services/music_service.dart`). It owns all playback state — current song, queue, shuffle/loop flags, volume — and calls `notifyListeners()` whenever something changes. Screens subscribe in `initState()`:

```dart
widget.musicService.addListener(_refresh);
```

This is Flutter's lightweight reactive pattern. Whenever the service changes, every listening screen rebuilds. No `Provider` or `Riverpod` needed for an app this size.

### 2. Background audio with platform notification

`main.dart` initializes `JustAudioBackground` before `runApp()`:

```dart
await JustAudioBackground.init(
  androidNotificationChannelId: 'com.example.cassette.channel.audio',
  androidNotificationChannelName: 'Cassette playback',
  androidNotificationOngoing: true,
);
```

This wires `just_audio` to the Android `MediaSession` API so playback continues when the app is backgrounded, and the system shows lock-screen controls. Each track gets a `MediaItem` tag in `_setSource()` (`music_service.dart:259`) so the notification shows the right title and artist.

### 3. Native code via MethodChannel (MediaStore scan)

Flutter doesn't expose Android's MediaStore API, so Cassette reaches into the platform layer with a `MethodChannel`:

```dart
static const _mediaStoreChannel = MethodChannel('cassette/media_store');
final raw = await _mediaStoreChannel.invokeMethod<List<dynamic>>('queryAudio');
```

The Kotlin side (under `android/app/src/main/kotlin/`) registers a handler for `queryAudio` and returns a list of audio entries (id, title, artist, duration, uri, file path). This is how Cassette finds music the user already has on their device — no third-party plugin, just direct platform interop.

### 4. Runtime permissions

Android 13+ split storage permissions into media-type permissions (`READ_MEDIA_AUDIO`). The `permission_handler` package handles the request flow:

```dart
var status = await Permission.audio.status;
if (!status.isGranted) status = await Permission.audio.request();
```

If denied, Cassette surfaces the failure via the `lastError` field instead of crashing.

### 5. Folder-priority sorting for scan results

After the MediaStore returns thousands of audio files (including ringtones and notification sounds), Cassette prioritizes paths under `/Music/`, `/Download/`, `/Downloads/` (`_folderPriority`, `music_service.dart:425`) and filters anything shorter than 10 seconds (`minDurationMs`). This keeps the library clean without manual curation.

### 6. URI scheme handling

Songs can be sourced from picked files (raw paths), MediaStore (`content://` URIs), or the file system (`file://` URIs). `_setSource()` (`music_service.dart:259`) and `_isLocalFileMissing()` (`music_service.dart:224`) branch on the URI scheme so each source type plays correctly and missing local files are auto-removed from the library.

### 7. Custom painter for the vinyl disc

The spinning disc on the player screen isn't an image — it's a `CustomPaint` widget (`_VinylPainter` in `lib/screens/player_screen.dart:290`). It draws concentric grooves with `canvas.drawCircle`, a radial gradient highlight, and an accent ring around the centered label. A `RotationTransition` driven by an `AnimationController` spins it while audio is playing.

### 8. Streams for live UI updates

The progress bar uses nested `StreamBuilder`s wired to `player.positionStream` and `player.durationStream` (`player_screen.dart:157`). The slider re-renders on every audio frame without manual `setState` calls.

### 9. JSON persistence in `SharedPreferences`

`StorageService` (`lib/services/storage_service.dart`) stores collections as `List<String>` where each entry is a JSON-encoded model. Songs and playlists implement matching `toJson()` / `fromJson()` constructors. This gives durable, structured storage without pulling in a database.

### 10. Material 3 theming with seed color + custom fonts

`AppTheme` (`lib/theme/app_theme.dart`) generates light and dark `ColorScheme`s from a single seed color (`#E8743B`, the cassette orange) using `colorSchemeSeed`. Two custom fonts are loaded via `pubspec.yaml`: `PlusJakartaSans` for body text and `Righteous` for the brand mark — exposed through `AppTheme.brand()`.

## Troubleshooting

- **"No songs yet" after scanning** — Android may have denied audio permission. Settings → Apps → Cassette → Permissions → enable Music and audio.
- **Hot reload doesn't pick up native changes** — Kotlin changes need a full restart (`Ctrl+F5`), not hot reload.
- **`flutter doctor` warns about Android licenses** — run `flutter doctor --android-licenses` and accept all.
- **App installs but won't launch** — `adb logcat | findstr cassette` while launching to see the crash.
